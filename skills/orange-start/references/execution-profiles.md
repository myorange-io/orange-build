# 실행 프로필, 요청 의도, 완료 수준

목표: 폴더 상태에 맞는 실행 방식을 고르고, 사용자가 선택한 완료 수준에서만 구현·검증한다. 숙련도를
평가하거나 묻지 않는다.

## 1. 실행 프로필

프로필은 `guided | adaptive` 두 개뿐이며 선택 질문을 하지 않는다.

### `guided`

- 비어 있거나 구현 코드가 없는 새 프로젝트
- `orange-start` 인터뷰로 기획서부터 만드는 작업
- 최신 App 기획서를 새 폴더에서 처음 구현하는 작업

필요한 설치·계정·첫 실행을 돕되, 준비된 항목을 다시 설명하거나 설치하지 않는다.

### `adaptive`

- 구현 코드와 runtime 설정이 있음
- Git 원격, CI 또는 배포 설정이 있음
- 프로젝트 고유 `AGENTS.md`, `CLAUDE.md`, README 실행 규칙이 있음

기존 명령·구조·배포 경로를 우선한다. 다른 framework나 공급자로 옮기지 않는다. 안전 게이트와 IA
단계 승인은 guided와 동일하다.

## 2. 요청 의도

| 요청 | `delivery_intent` | 종료 |
|---|---|---|
| 구현해줘, 만들어줘, 완성해줘 | `implement` | 승인받은 STEP을 순서대로 구현하고 선택한 완료 수준 검증 |
| 기획만, 계획만 | `plan_only` | `SOURCE_PLAN.md`, `PLAN.md`를 만들고 STEP-01 승인 대기 |
| 검증만, 점검만, 리뷰만 | `verify_only` | 현재 결과를 선택한 수준의 기준으로 검증하고 보고 |

`implement`는 모든 단계를 한 번에 실행하라는 뜻이 아니다. 매 STEP마다 승인과 결과 검토를 받는다.
사용자가 `배포하지 마`, `커밋하지 마`, `외부 발송하지 마`라고 제한하면 우선하고, 그 제한 때문에
선택한 수준을 증명할 수 없는 항목을 완료로 꾸미지 않는다.

## 3. 완료 수준

`completion_level`은 `local | shared | real_work` 중 하나다. 최신 기획서나 인터뷰 답을 사용하고,
모호하면 `phase-interview.md`의 `success_failure` 질문으로 한 번 확인한다.

### `local`

- 원격 저장소·배포·외부 발송·실데이터 변경을 요구하지 않는다.
- `web_app`: 로컬 핵심 흐름과 관련 오류·빈 상태·권한·모바일 조건
- `ai_skill`: 현재 호스트 개인 스킬 경로 등록과 새 작업 대표 호출
- `automation`: 외부 변경 없는 dry-run, 중복 방지, 제한 재시도, 로그

### `shared`

- 다른 사람이 접근하거나 설치해 같은 결과를 얻는지 확인한다.
- `web_app`: 실제 공유 URL과 대상 접근·저장 재조회
- `ai_skill`: 격리 또는 대상 환경 설치와 새 작업 호출
- `automation`: 공유 테스트 환경의 승인된 샘플 실행과 결과 재조회

### `real_work`

- 실제 자료·계정·업무 대상을 사용하고 복구·되돌리기 절차까지 확인한다.
- 배포·발송·실데이터 변경·자동화 활성화는 STEP 승인과 별도로 실행 직전에 다시 확인한다.

## 4. 준비와 저장 범위

- `local`은 원격·배포 계정·production 도구를 사전 준비에 넣지 않는다. 현재 STEP에 필요한 runtime과
  로컬 검증 도구만 확인한다.
- `shared`와 `real_work`는 기존 원격·CI·배포를 재사용한다. 실제로 필요할 때만 새 저장소나 프로젝트를
  제안한다.
- 기존 test·browser·CI가 검증할 수 있으면 새 MCP나 package를 제안하지 않는다.
- 모두 준비됐으면 준비 카드와 `PLAN.md` 갱신을 생략한다. 누락분만 변경분 준비 카드로 보여준다.
- 설치·권한·비용·외부 변경은 정확한 scope를 보여주고 동의받은 뒤 실행한다.

## 5. 진행과 완료 게이트

의미 있는 국면이 바뀔 때 현재 일과 다음 확인 결과를 1~2문장으로 알린다. 내부 명령 목록이나 평범한
commit 성공을 나열하지 않는다. 현재 STEP 결과를 보여준 뒤에는 반드시 세 선택지를 받고 기다린다.

`implement` 완료는 다음이 모두 있어야 한다.

- 모든 IA STEP이 `APPROVED`
- 모든 필수 REQ와 TEST가 계획한 증거 수준으로 PASS
- 선택한 `completion_level`과 결과물 유형에 맞는 실제 결과
- P0/P1, `FACT_UNVERIFIED`, 필수 사용자 행동이 남지 않음
- `MEMORY.md`에 선택한 완료 수준의 최종 검증 marker 블록이 정확히 하나 있음
- 남은 P2/P3와 미검증 항목을 숨기지 않은 보고

`shared`나 `real_work`에서 commit·push 또는 배포·활성화가 계약에 포함되면 정확한 파일만 저장하고
대상의 현재 상태를 재확인한다. `local`에는 원격 push나 production URL을 완료 조건으로 강요하지 않는다.
