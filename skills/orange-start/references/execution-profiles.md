# 실행 프로필과 완료 의도

목표: 교육 참가자의 안전한 완주 흐름은 유지하면서, 이미 코드와 도구가 있는 프로젝트에서는 준비된
내용을 다시 설명하거나 설정하지 않고 바로 구현한다. 사용자의 숙련도를 평가하거나 묻지 않는다.
현재 폴더의 상태와 사용자가 요청한 결과로만 분기한다.

## 1. 실행 프로필 판정

프로필은 `guided | adaptive` 두 개뿐이다. 프로필 선택 질문은 하지 않는다.

### `guided`

다음 중 하나면 guided다.

- 비어 있거나 구현 코드가 없는 새 프로젝트 폴더
- `orange-start` 인터뷰로 기획서부터 만드는 작업
- Orange Build App 기획서를 새 폴더에 붙여 처음 만드는 작업

현재의 준비 카드, 설치 보조, 계정 확인, 첫 배포, 초보자 보호장치를 모두 적용한다.

### `adaptive`

다음 증거 중 하나 이상이 있는 기존 프로젝트면 adaptive다.

- 실제 구현 코드와 package·runtime 설정이 있음
- Git 원격, CI workflow 또는 배포 설정이 있음
- 프로젝트 고유 `AGENTS.md`, `CLAUDE.md`, README 실행 규칙이 있음

adaptive는 안전장치를 없애는 모드가 아니다. 이미 준비된 것을 다시 묻거나 다시 설정하지 않고,
기존 프로젝트의 명령·구조·배포 경로를 우선하는 모드다.

판정한 값을 `PLAN.md` 메타데이터의 `execution_profile`에 기록한다. 기존 `PLAN.md`에 값이 없으면
폴더를 읽어 한 번 보강하고, 프로필 선택을 사용자에게 묻지 않는다.

## 2. 완료 의도 판정

사용자의 현재 요청을 다음 canonical 값으로 기록한다.

| 사용자가 원하는 것 | `delivery_intent` | 종료 조건 |
|---|---|---|
| 구현해줘, 만들어줘, 완성해줘, 끝까지 해줘 | `implement_and_release` | 결과물 구현·검증·저장·배포 또는 활성화까지 완료 |
| 기획만, 계획만 | `plan_only` | SOURCE_PLAN·PLAN 계약까지만 완료 |
| 검증만, 점검만, 리뷰만 | `verify_only` | 기존 결과 검증과 발견 사항 보고 |

`구현해줘`는 로컬 파일을 수정하거나 build만 통과한 상태를 뜻하지 않는다. 사용자 권한이나 외부
서비스 장애로 실제로 막히지 않는 한 다음 결과물별 릴리스 조건까지 계속한다.

- `web_app`: 기존 배포 경로가 있으면 그 경로, 없으면 Vercel production 배포를 사용해 실제 URL과
  핵심 흐름을 확인한다.
- `ai_skill`: 구현 파일·fixture·새 컨텍스트 호출을 검증하고 정확한 파일을 commit·push한다. 별도
  marketplace나 배포 대상이 기획서에 있으면 그 설치·활성화까지 확인한다.
- `automation`: dry-run뿐 아니라 승인된 샘플 live-run, 선택한 트리거 활성화, 최근 run과 결과
  재조회를 확인하고 commit·push한다.

사용자가 같은 요청에서 `배포하지 마`, `커밋하지 마`, `외부 발송은 하지 마`처럼 더 구체적인 제한을
말하면 그 제한이 우선한다. 제한은 `PLAN.md`의 `변경 기록`에 남기고, 제한 때문에 남은 릴리스 항목을
완료로 과장하지 않는다.

## 3. adaptive의 기존 프로젝트 우선순위

구현 전에 다음을 읽고 이미 정한 방식을 재사용한다.

1. `AGENTS.md`, `CLAUDE.md`, README의 프로젝트 규칙
2. `package.json#scripts`, pyproject·Makefile 등 기존 검증 명령
3. `.github/workflows/`, `vercel.json`과 다른 배포 설정
4. Git 원격·현재 브랜치·기존 변경

충돌하지 않는 한 위 프로젝트 규칙이 Orange Build의 Next.js·Vercel 기본값보다 우선한다. 기존
프로젝트를 다른 framework나 배포 서비스로 옮기지 않는다. 원격이 있으면 새 GitHub 저장소를 만들지
않고, 배포 경로가 있으면 새 Vercel 프로젝트를 만들지 않는다.

## 4. 사전 준비와 도움 도구

### guided

`phase-preflight.md`의 전체 준비 카드를 보여주고 필요한 설치를 한 번 동의받는다.

### adaptive

런타임·계정·도구·MCP를 읽기 전용으로 먼저 확인한다.

- 모두 준비됐으면 준비 카드를 생략하고 `PLAN.md` 상태만 갱신한다.
- 실제 누락이나 안전하지 않은 설정이 있을 때만 **변경분 준비 카드**를 한 번 보여준다.
- 기존 test·browser·CI가 요구사항을 검증할 수 있으면 새 MCP나 package를 제안하지 않는다.
- 설치·가입·권한이 구현을 막지 않으면 준비 단계 설명 없이 첫 REQ 구현으로 바로 간다.

시스템·글로벌·프로젝트 설치와 MCP 등록은 두 프로필 모두 정확한 변경 목록에 동의받은 뒤 실행한다.
삭제·결제·권한 확대·외부 발송·live 자동화 승인도 기존 안전 게이트를 유지한다.

## 5. 진행 보고

- `guided`: 기획 완료, 준비 완료, 첫 작동 결과, 최종 완료 이정표를 쉬운 말로 보여준다.
- `adaptive`: 시작 시 `REQ 수·기존 명령·배포 경로`, 실제 사용자 동작이 필요한 blocker, 첫 작동
  결과, 최종 결과만 보여준다. 내부 단계별 `✅` 보고는 생략한다.
- 두 프로필 모두 같은 질문이나 이미 확인한 상태를 반복하지 않는다.
- 단순 상태 설명으로 멈추지 않고 `delivery_intent`의 종료 조건까지 자동으로 이어간다.

## 6. 완료 게이트

`implement_and_release`는 다음이 모두 있어야 완료다.

- 모든 필수 REQ와 TEST가 계획된 증거 수준으로 PASS
- 결과물 유형에 맞는 라이브 URL·새 컨텍스트 호출·run id와 실제 결과
- 정확한 파일만 담은 commit과 원격 push
- 배포 또는 활성화 대상의 현재 상태 재확인
- 남은 외부 권한·P2/P3·미검증 항목의 정직한 목록

사용자 권한이나 외부 장애만 남았다면 완료라고 하지 않고, 사용자가 할 한 동작과 그 뒤 자동으로
이어갈 작업을 알려준다.
