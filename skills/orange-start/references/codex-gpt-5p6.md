# Codex GPT-5.6 실행 프로필

읽는 조건: 현재 호스트가 Codex일 때만 적용한다. 사용자가 Codex에서 GPT-5.6을 선택한다는 전제이며,
플러그인이 모델·추론 수준·계정 설정을 바꾸거나 별도 모델 도구를 설치하지 않는다.

## 1. 결과 계약을 주고 실행은 맡기기

GPT-5.6에 세부 작업 순서를 고정하지 않는다. 각 슬라이스마다 다음 네 가지를 명확히 한 뒤 조사·도구
선택·구현 순서는 모델이 정한다.

- 목표 산출물: 이번에 실제로 생겨야 하는 사용자 결과
- 보호 계약: `SOURCE_PLAN.md`, REQ·TEST, 이미 받은 사람 결정, 기존 프로젝트 규칙
- 완료 증거: 실행할 테스트와 사용자가 보게 될 관찰 결과
- 사람 게이트: 범위·비용·권한·삭제·외부 발송·계정 선택

성공한 것처럼 설명하는 문구보다 파일, 실행 결과, live 상태, 재조회 증거를 우선한다. 첫 성공 뒤에도
원본 대조와 인접 회귀 검증까지 자율적으로 이어간다.

## 2. 컨텍스트와 도구 라우팅

- 루트와 현재 경로의 `AGENTS.md`, 프로젝트의 기존 명령·CI·배포 설정을 먼저 적용한다.
- `SKILL.md`는 실행 지도만 유지하고 지금 단계에 필요한 `references/`만 읽는다. 모든 참고 파일과
  긴 로그를 한 번에 주 컨텍스트에 넣지 않는다.
- 저장소 안의 반복 절차는 스킬과 스크립트를, GitHub·브라우저·배포·데이터베이스처럼 외부 시스템은
  현재 연결된 도구나 MCP를 사용한다. 같은 능력의 MCP를 중복 설치하지 않는다.
- 독립적인 읽기·조회·검증은 묶어서 실행할 수 있다. 런타임이 programmatic tool calling을 제공해도
  단순 인벤토리·필터·정렬·검증처럼 중간 판단이 필요 없는 읽기 중심 작업에만 사용한다.
- 권한 변경, 결제, 삭제, 외부 발송, production 쓰기처럼 단계 사이에 새 판단이나 승인이 필요한 흐름은
  모델이 결과를 확인하며 순차 실행하고 사람 게이트를 지킨다.

## 3. 서브에이전트 사용 경계

다음 조건을 모두 만족할 때만 독립 작업을 서브에이전트에 위임한다.

1. 탐색·테스트·로그 분석·보안 검토·독립 완료 리뷰처럼 서로 독립된 작업이 두 개 이상이다.
2. 각 작업에 읽을 범위, 반환할 요약, 완료 조건을 짧게 지정할 수 있다.
3. 병렬화가 속도나 검증 품질을 실제로 높인다.

주 에이전트는 `SOURCE_PLAN.md`, `PLAN.md`, 사람 결정, 최종 통합과 완료 판정을 소유한다. 같은 파일이나
같은 실행 경계를 여러 에이전트가 동시에 수정하지 않는다. 쓰기 작업은 경로를 완전히 분리할 수 있을
때만 위임하고, 그렇지 않으면 주 에이전트 한 명이 수정한다. 외부 쓰기·배포·발송·삭제·계정 설정은
병렬 위임하지 않는다.

서브에이전트에는 구현자의 결론을 정답처럼 넘기지 않는다. 원본 계약, 확인할 범위, 기대할 증거를
주고 파일 위치가 포함된 짧은 결과를 받는다. 주 에이전트가 결과를 직접 대조하고 필요한 수정과 전체
회귀 검증을 끝낸다. 작은 작업이거나 조정 비용이 더 크면 한 에이전트로 진행한다.

## 4. 추론 수준과 실패 복구

- 모든 작업에 Max·Ultra를 강제하지 않는다. 현재 선택을 유지하고 작업 난도에 맞게 호스트가 제공하는
  능력을 사용한다.
- 같은 실패가 두 번 반복되면 추론 수준부터 올리지 말고 trajectory digest, 경쟁 가설, 가장 싼 판별
  검사로 `DIAGNOSE`한다.
- 긴 원시 로그와 탐색 결과는 요약하고, 주 컨텍스트에는 요구사항·결정·증거·다음 행동을 남긴다.
- 모델의 자신감이나 자기평가는 증거가 아니다. 실행한 테스트와 실제 관찰만 PASS로 센다.

## 5. 웹 UI에서의 역할

GPT-5.6의 레이아웃·시각 위계·디자인 판단은 구현 중 접근성, 반응형, 상태 완결성을 높이는 데
사용한다. 기능 구현 전에 별도 시안 탐색이나 Stitch 단계는 열지 않는다. 최종 검증 뒤 사용자가 디자인
개선을 요청한 경우에만 `orange-design`으로 전환한다.
